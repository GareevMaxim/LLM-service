# Smart Home AI Assistant (Hybrid RAG LLM Service)

Высокопроизводительный асинхронный ИИ-сервис на базе **FastAPI**, **LangGraph** и векторной базы данных **Qdrant** для умного поиска по технической документации, инструкциям и руководствам пользователя девайсов умного дома. 

Сервис принимает на вход файлы документов (`.pdf`, `.txt`), автоматически векторизует их локально без лишней нагрузки на LLM и позволяет пользователю через API задавать вопросы о починке, сбросе и настройке гаджетов. Система генерирует ответы строго на основе извлеченного контекста с использованием локальной модели **Llama 3.1**, развернутой через **Ollama**.

---

## Стек технологий
* **Пакетный менеджер:** [uv]
* **Инфраструктура:** Docker & Docker Compose (полная контейнеризация)
* **LLM-движок:** [Ollama](локальный запуск Llama 3.1)
* **AI-оркестрация и Агенты:** LangGraph & LangChain (архитектура ИИ-агента на базе графа состояний)
* **Векторное хранилище:** Qdrant (гибридный поиск)
* **Локальные эмбеддинги:** [FastEmbed] (ONNX-модели векторизации прямо в памяти Python)
* **Веб-фреймворк:** FastAPI (асинхронный API с поддержкой Server-Sent Events стриминга)
* **Тестирование:** Pytest + Pytest-Asyncio

---

## Архитектура ИИ-агента (Workflow)

Сервис построен на базе направленного графа состояний **LangGraph**, что гарантирует предсказуемость, безопасность и гибкость логики:

1. **`START` ➔ Модерация (`moderation_node`):** Входящий запрос проверяется на релевантность теме умного дома. Невалидные запросы сразу перенаправляются к Писателю за вежливым отказом.
2. **RAG Роутер (`rag_router_node`):** Оценивает запрос. Обучен выполнять *Query Expansion (расширение запроса синонимами и брендами)* и вызывать инструмент поиска `search_smart_home_docs` через структурированную привязку `bind_tools`.
3. **Гибридный поиск Qdrant (`custom_tools_wrapper`):** Извлекает контекст из Qdrant, используя одновременно два типа векторов (*Dense* для семантики смысла и *Sparse* для точечного совпадения ключевых слов). Результаты объединяются через алгоритм **RRF (Reciprocal Rank Fusion)** на стороне сервера Qdrant.
4. **Писатель (`writer_node`) ➔ `END`:** Принимает исходный вопрос пользователя и чистый контекст (очищенный от технических логов и служебных сообщений инструментов). Генерирует и пошагово стримит финальный ответ, прикрепляя в конце имя использованного файла.

## Быстрый старт

### 1. Подготовка окружения
Убедись, что на твоем компьютере установлен пакетный менеджер `uv` и Docker. Если `uv` еще нет, установи его одной командой:

### 2. Клонирование и установка зависимостей Python
```bash
git clone <ссылка на репозиторий>
cd job-postings-llm-main

# Создание изолированного виртуального окружения и синхронизация uv.lock
uv sync
```

### 3. Развертывание инфраструктуры в Docker
Запусти Docker-контейнеры в фоновом режиме:
```bash
docker compose up -d
```

> **Важно для Ollama (Первый запуск):** 
> При первом развертывании проекта на новом компьютере, контейнер Ollama будет пустым. Чтобы скачать языковую модель `llama3.1` внутрь контейнера, выполни в терминале следующую команду:
> ```bash
> docker compose exec ollama ollama run llama3.1
> ```
> *Благодаря настроенным Docker-томам (Volumes), модель весом ~4.7 ГБ скачается ровно один раз и полностью сохранится для всех последующих запусков.*



### 4. Конфигурация проекта (`.env`)
Создай файл `.env` в корне проекта для связи приложения с контейнерами:
```env
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://ollama:11434
OLLAMA_MODEL_NAME=llama3.1
QDRANT_URL=http://qdrant:6333
COLLECTION_NAME=smart_home_docs
PROMPTS_PATH=src/application/prompts
PYTHONUNBUFFERED=1
```
*Параметр `PYTHONUNBUFFERED=1` отключает внутренний буфер сети Python внутри Docker, что позволяет токенам Llama мгновенно улетать в сеть при стриминге.*

### 5. Инициализация гибридной базы знаний (Индексация)
Чтобы пересобрать структуру коллекции в Qdrant под гибридные индексы (dense + sparse) и залить исходные документы из папки `data_source/`, выполни скрипт инициализации:
```bash
PYTHONPATH=. uv run python src/infrastructure/db/init_vector_db.py
```

### 6. Запуск локального API сервера
После индексации ты можешь запускать веб-сервис:
```bash
uv run uvicorn src.api.main:app --reload
```
Открой встроенную интерактивную документацию Swagger по адресу: **`http://localhost:8000/docs`**.

## Эндпоинты API

* `GET /health` — Быстрая проверка статуса и здоровья микросервиса.
* `POST /api/v1/chat` — Классический синхронный эндпоинт. Ждет генерации полного ответа от Llama и возвращает JSON со структурой ответа и найденных документов.
* `POST /api/v1/chat/stream` — **Потоковый эндпоинт (Рекомендуется)**. Постепенно отдает текстовые токены в реальном времени по мере их генерации моделью. Swagger UI плавно анимирует и дописывает текст на экране, убирая эффект задержки. В самом конце стрима маркер `---METADATA---` передает список использованных источников.

## Тестирование

Проект на 100% покрыт автоматическими юнит-тестами с полной изоляцией. Тесты используют `unittest.mock` подмену: они не требуют запущенных контейнеров Ollama или Qdrant, не читают физические файлы промптов с диска и выполняются мгновенно.

Запуск панели тестирования:
```bash
uv run pytest -v
```

### Что покрыто тестами:
* Логика парсинга ответов от Qdrant, корректность обработки пустых результатов поиска и блоков перехвата исключений (`except Exception`).
* Поведение условных переходов внутри LangGraph воркфлоу (маршрутизация после модерации и RAG-агента).
* Очистка истории и правильная передача контекста в узлы агентов.
